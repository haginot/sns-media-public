An action defines how things get changed: parameters, submission criteria, rules applied in a single transaction, write-back, and a log of successful submissions. I call this whole set of constraints a "harness." That's my term, not Palantir's.

- Image: https://raw.githubusercontent.com/haginot/sns-media-public/e7f16a0b2ff868a414da49afda9e83ba8e87db1c/2026-11-16/zenn-ontology/en/figures/fig4.png (2000×1125 PNG, HTTP 200, SHA match)
- Alt: An action defines how things get changed. Five steps: ① Parameters (input types); ② Submission criteria (who, and in what state; can be submitted only when all are met); ③ Rules (create, modify, delete objects and links / function rules; applied in a single transaction); ④ Writeback and side effects (writeback dataset, business systems / notifications, webhooks); ⑤ Action log (records successful submissions only). The author’s view: this whole set of constraints is a “harness” (not a Palantir term). Example: change a flight's aircraft — only if the user is in the flight controllers group and the aircraft is in service.
